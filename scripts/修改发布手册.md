# 修改与发布手册 · 我们的时光簿

本文件记录日常修改、部署发布、故障排查所需的全部操作信息。配合 `scripts/交接说明.md` 使用。

## 一、环境与工具

- 终端：PowerShell（不要用 `&&`，用 `;` 或 `if ($?) { }`）
- 校验工具：`node --check <文件>` 检查 JS 语法
- 本地预览：`python -m http.server 8000`，浏览器开 http://localhost:8000
- 强刷页面：`Ctrl + Shift + R`（只清缓存，不会丢 Token）
- 禁止：不要引导用户"清除浏览器数据"（会删掉 Token）

## 二、发布（上线）完整流程

### 2.1 Token 准备

- 类型：GitHub fine-grained token
- 权限：`moment` 仓库的 Contents 读写；如需操作 Pages 设置再加 Pages 读写
- 生成地址：https://github.com/settings/tokens?type=beta
- 用途：浏览器端存 localStorage（管理页"保存并验证"），命令行部署时作为 Bearer token
- 安全：Token 不写进任何代码或文档

### 2.2 上传文件（PowerShell 模板）

```powershell
$token = '你的token'
$repo  = 'yuzengyang/moment'
$root  = 'G:\VS Code\Codex\workspaces\work\output\project2026-08-15\our-moments'
$headers = @{ Authorization = "Bearer $token"; Accept = 'application/vnd.github+json'; 'X-GitHub-Api-Version' = '2022-11-28' }

$files = @('index.html', 'assets/js/admin.js')   # 要上传的文件（相对路径）
foreach ($f in $files) {
  $local = Join-Path $root ($f -replace '/', '\')
  $api = "https://api.github.com/repos/$repo/contents/$f"
  $sha = $null
  try { $sha = (Invoke-RestMethod -Uri $api -Headers $headers -Method Get).sha } catch { }
  $body = @{ message = "update: $f"; content = [Convert]::ToBase64String([IO.File]::ReadAllBytes($local)); branch = 'main' }
  if ($sha) { $body.sha = $sha }
  $json = $body | ConvertTo-Json -Compress
  Invoke-RestMethod -Uri $api -Headers $headers -Method Put -Body ([Text.Encoding]::UTF8.GetBytes($json)) -ContentType 'application/json' | Out-Null
  Write-Output "OK $f"
}
```

要点：
- 先 GET 拿 sha（已存在文件必须带，否则 422）
- content 是文件字节的 base64（**单层**，图片不要二次编码）
- 网络偶发超时会报 JSON 解析错误，重试即可

### 2.3 验证发布

```powershell
(Invoke-RestMethod -Uri "https://api.github.com/repos/yuzengyang/moment/pages/builds/latest" -Headers $headers).status
```

- 等 1-2 分钟，状态变 `built`
- 或直接打开 https://yuzengyang.github.io/moment/ 检查

- 脚本会跳过 `photos.json` / `messages.json` / `photos/`（保护线上数据，勿移除）
- GitHub Pages 需在仓库 Settings → Pages 手动启用（main 分支 / root）

### 3.5 加新功能的一般流程

1. 数据层：`store.js` 加 `loadXxx / addXxx / deleteXxx`，照抄 `messages` 或 `comments` 的模式（有 token 写 GitHub，无 token 写本地）
2. 展示页：`gallery.js` 渲染 + `index.html` 加容器 + `gallery.css` 加样式
3. 管理页：`admin.js` 渲染 + `admin.html` 加面板 + `admin.css` 加样式
4. 测试：Node + vm mock（见本文第五节）
5. 上线：上传改动文件 → 等 Pages 构建 → `Ctrl + Shift + R` 验证

### 3.6 周计划评分规则

- 打分：`store.js` 的 `scorePlan(id, score, user)`，60 分及以上合格
- 状态：`planStatus(p)` 返回 `pending`（进行中）/ `scored`（已评分）/ `expired`（过期未评分）
- 过期后仍可评分（管理页 `refreshPlanPanel` 的 expired 分支带打分框）
- 截止时间：`submitPlan(content, user, targetDate)`，targetDate 为 YYYY-MM-DD，不传默认 7 天

### 3.7 照片可见性

- `photos.json` 每条照片 `visibility: 'public' | 'private'`
- 展览页三处读取都过滤 `private`；管理页显示全部
- 注意：这只是展示层隐藏，图片文件仍公开

## 六、故障排查手册

| 症状 | 可能原因 | 处理 |
| --- | --- | --- |
| 照片全是空位 | 图片 URL 失效或文件损坏（曾被双重 base64 编码） | 检查 `photos/` 文件是否为 JPEG（用 `file`/文件属性看类型）；损坏则解码一层 base64 后重传 |
| 上传/删除没反应 | 浏览器没 Token（走了本地模式） | 管理页看模式条，重新粘贴 Token 并"保存并验证" |
| 管理页周计划报错 | JS 引用未定义（曾因 fmtDateOnly 作用域） | F12 Console 看错误，`node --check`，确认函数在 common.js |
| 留言提交失败 | Worker 不可达或未配置 | 浏览器打开 worker 地址（GET 返回 not found 属正常），检查 Cloudflare 环境变量 |
| 评论不显示是谁 | 该浏览器没登录过管理页 | 先登录一次（写入 `om_user`） |
| 页面渲染崩溃 | TDZ / 语法错误 | F12 Console，检查变量声明顺序 |
| 强刷仍是旧版 | 浏览器缓存 | 再按 `Ctrl + Shift + R`，或换无痕窗口 |
| api.github.com 超时 | 网络波动 | 重试；脚本已对 GET 做重试 |
| raw 图片加载慢 | raw.githubusercontent 不稳定 | 已内置 jsDelivr / Pages 兜底，正常会自动切换 |
| 线上数据被覆盖 | 用本地空 JSON 覆盖了线上 | 从 GitHub 历史恢复（Commit 记录里找回旧版本） |

## 七、运维操作

- **备份**：GitHub 仓库首页 Code → Download ZIP（含代码 + 全部数据）
- **恢复单个数据文件**：仓库里点到该文件的 History，回滚到目标版本
- **清 Token**：管理页存储设置 → 清除
- **换 Token**：管理页粘贴新 Token → 保存并验证
- **数据文件**：仓库根目录 `photos.json`、`messages.json`、`plans.json`、`comments.json`；照片在 `photos/`
- **改仓库名/换仓库**：同时改 `common.js` 的 `SITE`、`store.js` 的 `GUESTBOOK_API`（若换域名）、`deploy.sh` 的 OWNER/REPO

## 八、安全红线

- Token 不写进代码、文档、对话公开处；泄露后立即在 GitHub 删除重建
- 登录密码明文是纯前端限制，真正的写权限由 Token 控制
- "仅我可见"照片只是展示层隐藏，文件仍可被知道 URL 的人访问；真正私密内容不要上传
- 不要用"清除浏览器数据"解决缓存问题（会丢 Token）
