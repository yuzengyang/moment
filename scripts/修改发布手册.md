## 二、发布（上线）完整流程

### 2.1 Token 准备

- 类型：GitHub **fine-grained** token，只授权 `yuzengyang/moment`，权限 **Contents: Read and write**
- 生成：<https://github.com/settings/personal-access-tokens/new>
- 两个用途，**都不写进代码或文档**：
  1. 浏览器端：管理页「存储设置」粘贴 →「保存并验证」，存 localStorage（key `om_token`），用于上传照片、发评论；
  2. 命令行部署：存 macOS Keychain（service `github-moment-token`），`deploy.sh` 自动读取。

```bash
# 存进 Keychain（按提示粘贴 token，不回显）
security add-generic-password -U -a "$USER" -s github-moment-token -w
# 验证有没有（只打印长度，不打印内容）
security find-generic-password -s github-moment-token -w | wc -c
```

### 2.2 发布方式 A：一键脚本（推荐）

```bash
cd /Users/zengyangyu/Deepseek/workspaces/web/projects/our-moments
export GITHUB_TOKEN=github_pat_xxx        # 或者不设，让它读 Keychain
bash scripts/deploy.sh
```

脚本做的事：确认仓库 → 逐文件 `GET 拿 sha → PUT 传 base64`（`branch: main`）→ 尝试启用 Pages。
**只跳过** `photos.json`、`messages.json`、`comments.json`、`plans.json`、`photos/` 和 `deploy.sh` 自己，
其余文件全部上传。

> ⚠️ 因为「其余全部上传」，发布前先确认目录里没有临时文件（`_t*.html`、`.DS_Store`、`*.pyc` 等），
> 否则会被一起推到线上。

### 2.3 发布方式 B：只传一两个文件（curl 模板）

```bash
cd /Users/zengyangyu/Deepseek/workspaces/web/projects/our-moments
TOKEN=$(security find-generic-password -s github-moment-token -w)
REPO=yuzengyang/moment
API=https://api.github.com

for f in assets/js/gallery.js index.html; do
  sha=$(curl -s -H "Authorization: Bearer $TOKEN" "$API/repos/$REPO/contents/$f" \
        | python3 -c "import sys,json;print(json.load(sys.stdin).get('sha',''))")
  b64=$(base64 < "$f" | tr -d '\n')          # BSD base64 没有 -w，必须这样去换行
  python3 - "$f" "$sha" "$b64" > /tmp/om_payload.json <<'PY'
import json, sys
rel, sha, content = sys.argv[1], sys.argv[2], sys.argv[3]
p = {"message": "update: " + rel, "content": content, "branch": "main"}
if sha: p["sha"] = sha
print(json.dumps(p))
PY
  curl -s -X PUT -H "Authorization: Bearer $TOKEN" -H "Accept: application/vnd.github+json" \
       --data-binary @/tmp/om_payload.json "$API/repos/$REPO/contents/$f" | head -c 120; echo
done
```

要点：

- 已存在的文件**必须**带 `sha`，否则 422；
- `content` 是文件字节的 base64，**单层**；照片不要二次编码（历史事故：照片被写成文本）；
- 大文件用临时文件传 `--data-binary @file`，避免命令行参数过长。

### 2.4 发布方式 C：SSH 直接 push（可选）

本机 SSH 已接通（`ssh -T git@github.com` 返回 `Hi yuzengyang!`）。只在**明确同意**时用，且不要覆盖别人的提交：

### 2.5 发布后验证

Pages 重建约 1–2 分钟。**不要用** `pages/builds/latest`——这个仓库实测返回 404。用「线上文件 vs 本地」的 SHA256 直接比：

```bash
cd /Users/zengyangyu/Deepseek/workspaces/web/projects/our-moments
for p in index.html assets/js/gallery.js assets/js/store.js; do
  live=$(curl -s "https://yuzengyang.github.io/moment/$p?v=$(date +%s%N)" | shasum -a 256 | cut -d' ' -f1)
  loc=$(shasum -a 256 "$p" | cut -d' ' -f1)
  [ "$live" = "$loc" ] && echo "OK   $p" || echo "DIFF $p"
done
```

- `?v=时间戳` 用来绕过 CDN 缓存；
- 页面还要人工看一眼：三页 200、Console 无报错、改的地方生效。

- `deploy.sh` 的跳过列表不要动（保护线上数据）

- 截止时间：`submitPlan(content, user, targetDate)`，`targetDate` 为 `YYYY-MM-DD`，不传默认 7 天

- `photos.json` 每条照片 `visibility: 'public' | 'private'`

## 六、故障排查

| 症状 | 可能原因 | 处理 |
| --- | --- | --- |
| 点上传没反应 / 提示「还没配置 GitHub Token」 | 浏览器没有 Token（换机、清缓存、过期） | 管理页存储设置粘贴 Token → 保存并验证 |
| 管理页顶部标红「Token 已失效」 | Token 过期或被 GitHub 撤销（401） | 重新生成，粘贴保存 |
| 评论框不出现 | 同上；评论只认 Token | 同上。登录过的设备会看到提示 |
| 照片全是空位 | 图片 URL 失效或文件损坏（曾被双重 base64 编码） | 检查 `photos/` 文件是否为 JPEG；损坏则解码一层后重传 |
| 管理页周计划报错 | JS 引用未定义（曾因 `fmtDateOnly` 作用域） | F12 Console，`node --check`，确认函数在 common.js |
| 留言提示「已先存到本机」 | Worker 不可达（网络/代理） | 打开 worker 地址确认；本机可 `curl --proxy http://127.0.0.1:7890` 测 |
| 留言提交失败 | Worker 未配置 `GITHUB_TOKEN` 或仓库权限不足 | Cloudflare 后台看环境变量 |
| 页面渲染崩溃 | TDZ / 语法错误 | F12 Console 看错误，`node --check` |
| 强刷仍是旧版 | Pages/CDN 缓存 | 再按 **Cmd + Shift + R**，或 URL 加 `?v=时间戳` |
| `api.github.com` 超时 | 网络波动 / 代理 | 重试；`curl` 需要代理时手动加 `--proxy` |
| 线上数据被覆盖 | 用本地空 JSON 覆盖了线上 | 仓库 History 找回旧版本 |

## 七、运维操作

## 八、安全红线

- Token 不写进代码、文档、对话；泄露后立即在 GitHub 删除重建
- 登录密码明文是纯前端限制，真正的写权限由 Token 控制；现在**两台设备各有一份 Token**，等同完整写权限（含删照片）
- 「仅我可见」照片只是展示层隐藏，文件仍可被知道 URL 的人访问；真正私密内容不要上传
- 不要用「清除浏览器数据」解决缓存问题（会丢 Token）
- 删除/批量替换文件、动目录结构前先说明范围
